# Sprint 01 Metrics & Telemetry Plan

Purpose: establish the metric artifacts each Sprint 01 mission must produce so the end-of-sprint evaluator (B1.6) can judge success criteria and inform planning.

## Artifact Directory Structure

- `cmos/reports/sprint-01/`
  - `presidio_corpus_baseline.json` – baseline precision/recall from synthetic corpus (B1.2)
  - `presidio_tuned_results.json` – tuned recognizer metrics post-integration (B1.3)
  - `ingestion_format_coverage.json` – per-format upload/redaction/chunking counts (B1.4)
  - `qdrant_performance.json` – embedding batch stats, latency, resource usage (B1.5)
  - `sprint-01-summary.md` – generated by B1.6 evaluator script

## Mission Telemetry Requirements

- **B1.1 Core Service Bootstrap**
  - Verify migrations with `pytest`/smoke test output (no persistent metric file required).
  - Document command(s) in README for use by evaluation script.

- **B1.2 Synthetic Corpus Pipeline**
  - Emit `presidio_corpus_baseline.json` with entity-level precision/recall, total synthetic docs per format, Faker locale coverage.
  - Store generation parameters in the JSON (seed, locales, counts) for reproducibility.

- **B1.3 Presidio Redaction Service**
  - Emit `presidio_tuned_results.json` capturing latest evaluation metrics, tuning adjustments, and comparison against baseline.
  - Include false-positive/false-negative samples (limited text with placeholders) when relevant.

- **B1.4 Document Ingestion Pipeline**
  - Emit `ingestion_format_coverage.json` summarizing for each priority format:
    - number of files processed
    - percentage successfully redacted + chunked
    - remaining TODOs or blockers.
  - Include mapping to sample document IDs generated from B1.2.

- **B1.5 Embedding & Qdrant Bootstrap**
  - Emit `qdrant_performance.json` covering:
    - embedding throughput (docs/hour, tokens processed)
    - Qdrant latencies (p50, p95, p99)
    - resource footprint & config parameters (m, ef_construct, quantization settings).

- **B1.6 Sprint Efficacy Evaluator**
  - Read above JSON artifacts and produce `sprint-01-summary.md` with:
    - success criteria verdicts
    - metric highlights
    - recommended follow-up missions or research.

## Process Notes

- Each mission owner is responsible for writing their metric artifact to the designated filename so the evaluator can run without modifications.
- Intermediate notebooks or logs should reference these filenames to avoid duplication.
- Reports must be checked into version control unless they contain synthetic PII that should remain local; keep raw generated documents out of git per R1.1 guidance.
