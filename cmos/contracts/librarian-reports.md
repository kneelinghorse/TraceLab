# Reviewed report previews (LIB-4)

Decision #557 implements the [Librarian roadmap](../foundational-docs/roadmap-sprints-57-60-the-librarian.md) and the [durable report citation contract](collection-context-and-reports.md#durable-local-report-citations-report-1-sprint-60). The guiding architecture template is [tech_arch_template.md](../foundational-docs/tech_arch_template.md).

`GET /librarian/reports/sources?project_id=…&collection_id=…` returns up to 100 eligible actual saved excerpts, their complete supplied text and character counts, canonical chunk links, coverage counts and a signed seven-day source snapshot. Collection input follows reviewed member order; project input follows document/chunk order. Only current readable, live, selected-project sources are eligible, even for admins. Empty/over-4,000-character excerpts are excluded and disclosed. Readable other-project collection members are counted as excluded; their identities/text are never included. Direct document membership is never silently expanded into excerpts.

`POST /librarian/reports/draft` requires `project_id`, `source_token`, an ordered unique selection of 1–12 `chunk_ids`, `reviewed_sources: true`, title (1–255), prompt (1–4,000), and format (`summary`, `report`, `bullets`, `markdown`). Selection must be within the source snapshot and at most 24,000 characters. It is never silently shortened. Sources, collection membership and permissions are checked before the provider and again afterward; database locks are released across the provider call. One configured Librarian JSON call has a 4,000-token output cap and 12,000-character content cap. There is no automatic repair, cache call or generation on page load. Returned paid usage is attributed once, including refusal or malformed/truncated output.

The shared REPORT-1 validator requires supplied numeric markers on prose blocks/list items. It validates marker identity and coverage, not semantic entailment. Unsupported, empty, malformed or incomplete output returns a recoverable refusal, not a savable proposal. The preview retains exact content, sparse citation markers, all effective source IDs, title/prompt/format/model and generation time. Its seven-day signed token binds those values and source hashes to the caller, selected project, original collection and stable Report UUID. Tokens are private client state, never logs or acceptance receipts.

`POST /librarian/reports/accept` takes only `project_id` and `proposal_token`; the client cannot supply replacement prose, citations or ownership. Fresh human/project/create access, current collection access/membership and every effective input's liveness, hash and selected-project membership are rechecked, including inputs not cited in the final prose. The project row is locked before source checks. Existing Report, ReportSource and IdempotencyRecord rows commit atomically; no second provider call and no partial report are possible. A repeated proposal returns the authorized existing Report and preserves later human metadata edits. A durable receipt prevents recreating a deleted Report. Expired or stale proposals require a fresh explicit source review/draft; already saved reports remain accessible through their normal link.

Provenance records Librarian origin/model/requesting user/generation time and human accepting user/time, with no raw source identities outside the existing scoped citation/source fields. The Report is a draft owned by the caller in the selected project, using the existing default workspace assignment and project access inheritance. No migration or ownership/RBAC changes are introduced. The existing report page, exports and published MCP getter consume the artifact. The three conversational operations are REST-only by design in the parity manifest.

Browser state uses caller/project keys. Loading excerpts, browsing collections, selecting sources and dismissal cause no model or research writes. Changing inputs requires intentional regeneration before save. Navigation/reload retains the exact proposal and saved link; late responses after identity switches are ignored. A failed save can retry the same signed proposal. Full supplied text, filtered membership, limits, preview citations and the save boundary are visible before acceptance.
