# B19.3 HNSW Parameter Tuning Results

**Date**: 2025-12-10
**Mission**: B19.3 - HNSW Parameter Tuning
**Status**: Completed

## Objective

Tune Qdrant HNSW parameters to optimize for lower latency while maintaining acceptable recall. Target 30-50% latency reduction with <5% recall degradation.

## Benchmark Environment

- **Collection**: `research_chunks`
- **Points**: 7,245 documents
- **Trials**: 20 random queries per ef_search value
- **Top-K**: 10 results per query
- **Baseline**: ef_search=128

## Results Summary

| ef_search | Avg Latency (ms) | P95 Latency (ms) | P99 Latency (ms) | Recall |
|-----------|-----------------|------------------|------------------|--------|
| 32        | 41.8            | 45.6             | 45.9             | 100%   |
| 48        | 42.7            | 47.9             | 51.8             | 100%   |
| 64        | 40.7            | 49.5             | 49.9             | 100%   |
| 96        | 47.6            | 67.7             | 101.8            | 100%   |
| 128       | 46.5            | 63.9             | 91.7             | 100%   |

## Key Findings

1. **All ef_search values maintain 100% recall** at current corpus size (7K points)
2. **ef_search=64 offers best latency/recall balance**:
   - ~40ms avg latency (vs 47ms baseline)
   - ~50ms p99 latency (vs 92ms baseline)
   - **45% p99 latency improvement**
3. **ef_search=32-48** also viable but provide minimal additional benefit
4. **ef_search=96+ shows diminishing returns** with higher latency variance

## Configuration Changes

### app/core/config.py
Added configurable HNSW default:
```python
# HNSW tuning: ef_search controls recall/latency trade-off (B19.3)
qdrant_hnsw_ef_default: int = 64  # Optimized default (was 128)
```

### app/services/retrieval_service.py
Updated `recommend_hnsw_ef()` with optimized tiers:
```python
def recommend_hnsw_ef(self, top_k: int) -> int:
    base_ef = settings.qdrant_hnsw_ef_default  # 64 by default

    if top_k <= 5:
        return base_ef          # 64
    if top_k <= 10:
        return max(base_ef, 72) # 72
    if top_k <= 20:
        return max(base_ef, 96) # 96
    return min(128, max(base_ef, int(top_k * 4)))
```

### app/services/qdrant_service.py
Updated `search_chunks()` to use configurable default:
- Changed `hnsw_ef: int = 128` to `hnsw_ef: Optional[int] = None`
- Defaults to `settings.qdrant_hnsw_ef_default` when not specified

## Rollback Procedure

To rollback to previous behavior:
1. Set `QDRANT_HNSW_EF_DEFAULT=128` in environment
2. Or edit `app/core/config.py`:
   ```python
   qdrant_hnsw_ef_default: int = 128
   ```

## Notes

- **ef_search is query-time parameter**: Changes take effect immediately without rebuilding index
- **Recall at scale**: At larger corpus sizes (50K+ points), may need to increase ef values
- **Monitoring recommended**: Track recall metrics in production to detect degradation
