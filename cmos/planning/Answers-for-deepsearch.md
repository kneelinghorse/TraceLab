## Data Model & Schemas

### Mission (Mission Protocol)

**Pydantic Model:** `app/models/mission_protocol.MissionProtocolDraft` / `MissionProtocolComplete`

**Key Fields:**
```python
mission_id: str              # Required, e.g., "DRM.0.5"
version: str                 # Default "1.0.0"
title: str                   # Required for completion
summary: Optional[str]
project_id: Optional[str]    # Links to Project
status: MissionStatus        # "draft" | "in_progress" | "review" | "complete"
owner: Optional[str]

# Core research fields
research_statement: ResearchStatement  # topic, objective, scope
key_questions: List[KeyQuestion]       # question, status, answer
synthesis: Synthesis                   # key_insights, recommendations, contradictions
evidence: List[Evidence]               # evidence_id, source, chunk_id, insight_id
quality_checkpoints: List[QualityCheckpoint]  # gate, status, validated_at

tags: List[str]
created_at: Optional[datetime]
updated_at: Optional[datetime]
```

**Database Storage:** PostgreSQL `missions` table
- `mission_data` (JSON) - Full Mission Protocol structure
- `quality_gates` (JSON) - Gate validation results
- `status`, `completion_percentage` - Progress tracking
- Foreign key to `projects`

## Entity Relationships

```
Project (1) → (many) Missions
Project (1) → (many) Documents
Project (1) → (many) Insights

Document (1) → (many) DocumentChunks (auto-generated)
Insight (many) ↔ (many) DocumentChunks (via insight_sources junction)

Mission references:
- Linked to Project via project_id
- mission_data.evidence[] contains chunk_id references
```

**Key Point:** Mission is linked to Project. Documents are also linked to Project. Chunks are auto-created by TraceLab from Documents.

## Quality Gates - What Causes 422 Errors

**5 Required Gates for Completion:**

1. **research_statement** - `topic`, `objective`, and `scope` must all be non-empty
2. **evidence_links** - At least 1 evidence item with `chunk_id` reference
3. **contradictions_resolved** - Every `synthesis.contradictory_information[]` item needs matching resolution
4. **synthesis_quality** - Key insights ≥40 chars, at least 1 recommendation, at least 1 next step
5. **traceability** - All evidence items have `chunk_id` references

**Validation Errors:**

**Required Fields (422):**
- Missing `mission_id`
- Missing `title` (for complete state)
- Missing `research_statement` (for complete state)
- Missing `synthesis` (for complete state)

**Business Rules (422):**
- Marking status="complete" without all 5 gates passing
- Evidence list empty on completion
- No answered key questions
- Empty `synthesis.key_insights[]`

**Format Constraints:**
- `mission_id` cannot be blank/whitespace
- Dates must be valid ISO 8601 format
- UUIDs must be valid format for `project_id`, `chunk_id` references

## API Design - Agent Integration

### Recommended Approach: Single Mission Creation Endpoint

**POST /api/v1/missions**

**Request Body:**
```json
{
  "project_id": "uuid-of-project",
  "mission_data": {
    "mission_id": "DRM.0.5",
    "title": "Research passwordless auth patterns",
    "research_statement": {
      "topic": "Passwordless authentication",
      "objective": "Identify implementation patterns",
      "scope": "Web applications, 2020-2025"
    },
    "key_questions": [
      {
        "question": "What are common passwordless methods?",
        "status": "answered",
        "answer": "Magic links, WebAuthn, OTP codes"
      }
    ],
    "synthesis": {
      "key_insights": ["Magic links most popular for consumer apps"],
      "recommendations": ["Implement WebAuthn for security-critical apps"],
      "next_steps": ["Prototype WebAuthn flow"]
    },
    "evidence": [
      {
        "evidence_id": "EV-001",
        "source": "Web search results on passwordless auth",
        "content": "Summary of findings...",
        "chunk_id": "uuid-of-chunk-if-available"
      }
    ],
    "quality_checkpoints": [
      {"gate": "research_statement", "status": "pass"},
      {"gate": "evidence_links", "status": "pass"},
      {"gate": "synthesis_quality", "status": "pass"},
      {"gate": "traceability", "status": "pass"},
      {"gate": "contradictions_resolved", "status": "pass"}
    ]
  }
}
```

**Response (201 Created):**
```json
{
  "id": "uuid-generated-by-tracelab",
  "project_id": "uuid-of-project",
  "mission_data": { ... },

  "quality_gates": { ... },
  "created_at": "2025-11-15T21:00:00Z",
  "updated_at": "2025-11-15T21:00:00Z"
}
```

### Document Creation Flow

**Separate Workflow: Documents created independently, then chunks auto-generated**

**Step 1: Create Document**
```
POST /api/v1/documents/upload
Content-Type: multipart/form-data

file: [binary file or markdown text]
project_id: uuid
file_type: "report"
source_type: "analysis"
```

**Step 2: Process Document (auto-chunks)**
```
POST /api/v1/documents/{document_id}/process
```

This triggers:
- Text extraction (if PDF/DOCX)
- Chunking (500-1000 tokens, 50 token overlap)
- Embedding generation (OpenAI text-embedding-3-small)
- Storage in Qdrant

**Result:** `document_chunks` table populated, `embedding_id` references created

**Step 3: Reference chunks in Mission evidence**
```json
{
  "evidence": [
    {
      "evidence_id": "EV-001",
      "source": "DeepSearch research report",
      "chunk_id": "uuid-from-chunks-table"
    }
  ]
}
```

---

### Alternative: Agent Provides Markdown, TraceLab Chunks

**If DeepSearch generates markdown report:**

1. **POST /api/v1/documents/upload** - Upload report as markdown
2. **POST /api/v1/documents/{id}/process** - Auto-chunk and embed
3. **GET /api/v1/documents/{id}/chunks** - Retrieve generated chunks
4. **POST /api/v1/missions** - Create mission referencing chunk IDs

**Benefit:** TraceLab handles all chunking/embedding logic consistently.

## Integration Architecture (DRAFT - being finalized)

**Flow A: DeepSearch → TraceLab (Write)**
```
1. DeepSearch completes research
2. Generates JSON matching MissionProtocolComplete schema
3. POST /api/v1/missions with full payload
4. TraceLab validates via Pydantic
5. Quality gates auto-check
6. If pass: stored in PostgreSQL + Qdrant
7. If fail: 422 error returned → DeepSearch correction loop
```

**Flow B: DeepSearch → PEDR → TraceLab (Read-before-Write)**
```
1. DeepSearch receives research question
2. First queries PEDR: "Does this research already exist?"
3. If yes: Skip external research, use existing
4. If no: Proceed with web search loops
```

**Flow C: User → TraceLab → RAG Synthesis**
```
1. User asks: "What have we learned about auth?"
2. TraceLab RAG queries across all stored missions
3. Synthesizes answer from accumulated research
4. Returns with citations to source missions/chunks
```

## Key Recommendations

1. **Start simple** - Markdown output → manual upload → validate flow
2. **Use existing models** - Don't create custom schemas, match `MissionProtocolDraft`
3. **Chunks are auto-generated** - Don't try to create chunks, let TraceLab handle it
4. **Quality gates are your friend** - They ensure output quality, use them to validate agent work
5. **Error handling later** - Get happy path working first, add correction loops in Sprint 3-4
