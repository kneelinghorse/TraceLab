# Collection context and report citations (UX-8)

Guiding plan: [UX overhaul roadmap](../foundational-docs/roadmap-sprints-50-53-ux-overhaul.md). Composition follows the [OODS object mapping](oods-object-model.md), interaction follows [frontend hygiene](frontend-hygiene.md), and seed authoring follows the [mission boundary contract](mission-authoring-contract.md#collection-context-seed-ux-8-2026-09-13).

Collections retain their name, description and excerpt membership, and add nullable instructions (maximum 20,000 characters). Migration 046 adds `collections.instructions` and a separate `collection_documents` join table with cascading foreign keys. Direct membership supports source documents before processing; it does not manufacture chunks or relax the existing 100-excerpt collection limit.

Authenticated `/collections/{id}/documents` supports GET (page, page_size up to 100), POST (`document_id`, idempotent), and DELETE `/{document_id}`. Context is the distinct union of direct documents and documents referenced by saved excerpts. Documents and their parent projects must be live and within the caller's read scope. Policy 1.1 additionally lets a human project owner read every non-deleted document in that live project, including documents owned by other users, without Space membership (decision #424). This is an ownership match, not the privileged owner role, and grants no document writes or service-principal access. Authorization precedes counting, paging and writes. Removing a document detaches both forms of membership without deleting the document or its chunks. SQLite and PostgreSQL use their native conflict-safe insert; upgrade, downgrade and cascade behavior are covered against real PostgreSQL.

The read-only `/collections/{id}/mission-seed` response includes all readable context documents, independently of the document-list page. Instructions and source identities populate existing background, structured references and context fields; one source project is preselected, while mixed or empty context requires a project choice. `/missions/new?collection={id}` reviews those inputs before the existing save, contract-preview and submit lifecycle. References record provenance; they do not impose an additional worker access boundary. Reference edits preserve the exact row identity and structured metadata, including when source documents share a filename. No MCP schema or worker SELECT field changes.

The collection picker uses the shared mounted Dialog, complete server collection totals, and either document or excerpt attachment. If creation succeeds but attachment fails, retry uses the same collection. Collection detail edits instructions and exposes document paging, removal, mission seeding and the existing excerpt/report/export controls. Existing routes remain canonical; the new authoring query is not a route migration.

RBAC-enabled collection detail, count, export and excerpt addition enforce the shared `app/services/document_policy.py` policy as well as project scope. Report creation and `/synthesize` resolve the same readable chunk subset before provider initialization or cache use, including for privileged owner/admin callers, and persist only effective synthesis sources. Deleted documents and deleted parent projects are excluded on both direct-chunk and collection inputs; empty subsets never initialize the provider or consult its cache. Collection ordering follows addition time then chunk ID; direct inputs follow chunk ID. Explicit flag-off/internal legacy service calls retain their prior optional-argument behavior. Existing role, Space and write grants are unchanged.

Reports use server totals and status/project filters. Citation destinations come only from the existing scoped Evidence API with `report_id`: persisted ledger entry sources, independently readable result missions, and literal HTTP(S) citations in report content. Counts and pagination apply after that relationship filter and the existing evidence policy. A raw ReportSource identifier is not a permission grant. Project owners and Space members retain their existing evidence access; unrelated cross-project source records cannot expand it.

Markdown, JSON and text export content bytes are unchanged. Download headers now supply an ASCII fallback and UTF-8 filename for titles that previously produced invalid headers. Tests preserve Unicode content, citation URLs and whitespace. Report creation keeps the mounted shared Dialog and restores focus on dismissal.

Validation includes >100 distinct context documents, revoked/hidden/deleted source checks, complete authoring references through the actual MCP client handler, all citation relationship paths and outside-Space denial, export byte fixtures, full frontend units and built-browser flows in Light/Dark at 390/820/1440. Deployment and production acceptance evidence belongs in `../reports/sprint-51/ux-8-validation.json`.

## Durable local report citations (REPORT-1, Sprint 60)

Decision #552 and the [Librarian handoff](../planning/sprint-60-HANDOFF.md) extend the contract above. Migration 053 adds nullable JSON/JSONB `Report.citation_manifest` and `generation_provenance`. Null means no provable legacy mapping, including automatic DeepSearch reports. No historical backfill, conversion or regeneration occurs. ReportSource inputs and Evidence relationships keep their separate meanings.

Each generated manifest entry retains its original positive numeric `marker`, chunk/document identity and SHA-256 of the non-empty text actually supplied. Sparse and repeated markers are never renumbered. Both synthesis writers persist the manifest and effective input subset in the report transaction after rechecking source access and liveness. No supplied evidence, unknown markers or uncited claim blocks fail closed through the existing Librarian provenance rules. Headings are structural; prose blocks and list items require citations. This validates citation identity and coverage, not semantic entailment. The existing 50-chunk and 100,000-character budgets remain; sources beyond either cap are not effective inputs. Cache identity includes ordered supplied text and model, and cached markers are revalidated.

Create/detail/update/JSON export add `citation_status` (`validated` or `legacy_unavailable`), server-produced generation provenance, and numbered citations. Available citations include an excerpt and canonical `/documents/{id}?chunk={id}&index={n}` destination. Unavailable entries retain only the marker and availability flag; permission checks precede source text, identifiers and destinations. A changed source hash is unavailable rather than retroactively supporting old prose. Authored report content is retained. Independently authorized mission result Documents may appear as original documents, never as proof of numbered claims.

Generation provenance records origin, model, requesting user, generation time and cache reuse. Existing one-call generation does not imply review: accepted user/time remain null until LIB-4's explicit acceptance workflow. Prompt and effective source identities remain on the Report and its source records. New Markdown/text exports append numbered, scoped source destinations; legacy Markdown/text bytes remain unchanged. JSON additions are backward-compatible. Existing MCP handlers forward citation objects unchanged; deployed-client regression is required without introducing a new tool.

## Explicit collection acceptance (ORG-1, Sprint 60)

The [reviewed-collection contract](librarian-collections.md), decisions #555/#556, adds nullable generation provenance and per-item reviewed positions in migration 055. Position precedes the existing time ordering for collection detail, export and synthesis/report inputs; legacy null positions preserve their prior ordering. A signed caller/project proposal creates only its explicitly accepted group through CollectionService, with current source checks, immutable accepted membership and durable idempotency across partial retry or later deletion. The detail response's `librarian_generated` flag enables a separate scoped origin view; existing MCP fields are unchanged. No project foreign key, automatic source move, tag rewrite or Space grant is added.

## Reviewed Report acceptance (LIB-4, Sprint 60)

The [reviewed-report contract](librarian-reports.md), decision #557, adds explicit source selection, a signed cited preview and atomic acceptance of that exact content without a second generation. It uses the existing Report/citation/provenance fields and scoped reads/exports. Source lists visibly filter a collection to one selected project and never expand whole-document membership. All effective sources are checked again before save. Stable proposal identity and a durable receipt prevent duplicate creation or resurrection after deletion. No new MCP action or migration is required.
